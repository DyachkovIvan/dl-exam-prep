# Тема 7. Рекуррентные сети: RNN, BPTT, BiRNN, LSTM, GRU

## 7.1 Vanilla RNN

Обрабатывает последовательность x₁,…,x_T, сохраняя **скрытое состояние** h_t ∈ ℝʰ (память):
$$h_t = \tanh(W_{hh}h_{t-1} + W_{xh}x_t + b_h), \qquad y_t = W_{hy}h_t + b_y, \qquad h_0 = 0$$

Ключевое: **веса общие для всех шагов времени** (weight sharing по времени) → сеть работает с последовательностями любой длины, а число параметров от T не зависит.

**Число параметров** (вход x ∈ ℝⁿ, состояние h, без выходного слоя): h·h + h·n + h = h(h + n + 1).

**Типы задач:** many-to-one (классификация текста), one-to-many (генерация подписи), many-to-many синхронно (разметка токенов, NER), many-to-many с задержкой (перевод, seq2seq).

## 7.2 Backpropagation Through Time (BPTT)

Идея: **развернуть** (unroll) рекуррентную сеть по времени в глубокую feedforward-сеть с T слоями, у которых одинаковые веса, и применить обычный backprop.

Порядок:
1. Forward по всем T шагам, сохраняя все h_t.
2. Считаем суммарную потерю L = Σ_t L_t.
3. Backward с последнего шага к первому.
4. Градиенты по W со всех шагов **суммируются** (потому что веса общие).

**Формально.** Градиент по рекуррентной матрице:
$$\frac{\partial L}{\partial W_{hh}} = \sum_{t=1}^{T}\sum_{k=1}^{t} \frac{\partial L_t}{\partial h_t}\Bigg(\prod_{j=k+1}^{t}\frac{\partial h_j}{\partial h_{j-1}}\Bigg)\frac{\partial^{+} h_k}{\partial W_{hh}},
\qquad
\frac{\partial h_j}{\partial h_{j-1}} = \operatorname{diag}\big(1-h_j^2\big)\,W_{hh}$$

∂⁺h_k/∂W — «непосредственная» производная на шаге k, при фиксированном h_{k−1}. Вклад шага k в потерю на шаге t проходит через **произведение t−k якобианов**.

**Чем отличается от backprop в feedforward-сети (прямой вопрос билета):**
- градиент распространяется не только «по слоям», но и **назад во времени**;
- одни и те же веса получают вклад с каждого временного шага → градиенты суммируются;
- эффективная глубина = длина последовательности → сильные проблемы затухания/взрыва градиента;
- нельзя параллелить по времени (в отличие от CNN/трансформера): h_t зависит от h_{t−1};
- на практике используют **Truncated BPTT** — градиент протягивают только на k шагов назад, иначе слишком дорого по памяти.

**Почему градиент затухает или взрывается — точная формулировка** (Pascanu, Mikolov, Bengio, 2013). Пусть λ₁ — наибольшее сингулярное значение W_hh, а γ — верхняя граница |σ'| (γ = 1 для tanh, γ = 1/4 для sigmoid). Тогда
- **λ₁ < 1/γ — достаточное условие затухания:** ‖∂h_j/∂h_{j−1}‖ ≤ γλ₁ < 1, произведение убывает экспоненциально, сеть не помнит далёкий контекст;
- **λ₁ > 1/γ — необходимое (но не достаточное) условие взрыва.**

**Лечение взрыва — gradient norm clipping** (из той же статьи):
$$\text{если } \|g\| \ge \tau:\quad g \leftarrow \frac{\tau}{\|g\|}\, g$$

Направление градиента сохраняется, ограничивается только длина шага. Затухание clipping не лечит — для него нужны гейтовые архитектуры.

## 7.3 LSTM (Long Short-Term Memory)

Hochreiter & Schmidhuber, 1997; forget gate добавлен позже (Gers et al., 2000). LSTM решает затухание введением **состояния ячейки c_t** — «конвейера памяти», по которому градиент течёт почти без затухания (аддитивное обновление вместо мультипликативного). Поток информации регулируют три **вентиля (gates)** на сигмоидах. Здесь [h_{t−1}, x_t] — конкатенация векторов.

**Вентили и кандидат:**
$$f_t = \sigma(W_f[h_{t-1},x_t]+b_f) \quad \text{— forget gate: что стереть из памяти}$$
$$i_t = \sigma(W_i[h_{t-1},x_t]+b_i) \quad \text{— input gate: что записать}$$
$$o_t = \sigma(W_o[h_{t-1},x_t]+b_o) \quad \text{— output gate: что показать наружу}$$
$$\tilde c_t = \tanh(W_c[h_{t-1},x_t]+b_c) \quad \text{— кандидат новой информации}$$

**Обновление памяти и выход:**
$$c_t = f_t \odot c_{t-1} + i_t \odot \tilde c_t$$
$$h_t = o_t \odot \tanh(c_t)$$

**Почему это лечит затухание — формально.** По прямой линии ячейки:
$$\frac{\partial c_t}{\partial c_{t-1}} = \operatorname{diag}(f_t) \quad(+\text{ вклады через вентили, зависящие от } h_{t-1})$$

Здесь **нет умножения на матрицу весов и на производную tanh**. Если сеть держит f_t ≈ 1, градиент проходит через сотни шагов почти без изменений (идея «constant error carousel» из исходной статьи). Сеть сама **учится**, когда помнить, а когда забывать. Практический трюк — инициализировать bias forget gate единицей, чтобы в начале обучения f_t ≈ 0.73 и память по умолчанию сохранялась (Jozefowicz et al., 2015).

**Как работает LSTM в двух фразах:** ячейка хранит долговременное состояние; три вентиля (сигмоиды, выдающие числа 0..1) решают, сколько старой памяти забыть, сколько новой информации записать и сколько памяти показать наружу. Аддитивная линия c_t даёт «градиентную магистраль» → сеть помнит длинный контекст.

**Параметры:** 4 набора (f, i, o, c̃) → 4·h(h + n + 1). В PyTorch два вектора bias на каждый набор — 4·(h(h+n) + 2h).

## 7.4 GRU (Gated Recurrent Unit)

Cho et al., 2014. Упрощение LSTM: **два** вентиля, **нет отдельного состояния ячейки** (только h_t).

**Вентили:**
$$z_t = \sigma(W_z[h_{t-1},x_t] + b_z) \quad \text{— update gate (объединяет forget и input)}$$
$$r_t = \sigma(W_r[h_{t-1},x_t] + b_r) \quad \text{— reset gate}$$

**Кандидат и обновление:**
$$\tilde h_t = \tanh(W[r_t \odot h_{t-1},\ x_t] + b)$$
$$h_t = (1-z_t)\odot h_{t-1} + z_t \odot \tilde h_t$$

**Смысл:**
- h_t — **выпуклая комбинация** старого состояния и кандидата. При z_t ≈ 0 состояние копируется без изменений — та же «магистраль» для градиента, что в LSTM.
- Reset gate r_t решает, насколько прошлое состояние учитывать при построении кандидата.

> ⚠️ В литературе две конвенции: в статье Cho et al. и в PyTorch h_t = z_t⊙h_{t−1} + (1−z_t)⊙h̃_t, то есть роль z «перевёрнута». Суть не меняется — на экзамене достаточно явно сказать, какую конвенцию используете.

**LSTM vs GRU:** у GRU 3 набора весов против 4 → **3/4 параметров** LSTM; быстрее обучается, часто сопоставимое качество. LSTM бывает лучше на очень длинных последовательностях и больших данных; LSTM разделяет «память» c_t и «выход» h_t.

## 7.5 Двунаправленные RNN (BiRNN)

Два независимых RNN: один читает последовательность слева направо, другой — справа налево; состояния конкатенируются: h_t = [h_t^→ ; h_t^←].

**Плюсы:** каждый момент времени видит **и прошлый, и будущий контекст** → заметно лучше для NER, разметки частей речи, классификации текста.

**Минусы:**
- **Не применима к онлайн/потоковым задачам и авторегрессионной генерации** — нужна вся последовательность целиком (для генерации будущее ещё не известно).
- Параметров и вычислений вдвое больше.

## 7.6 Регуляризация и приёмы обучения RNN

- **Dropout:** применяется к входам/выходам слоя и **между слоями**, но не к рекуррентной связи в наивном виде — новая маска на каждом шаге разрушает память. Правильный вариант — **variational (recurrent) dropout** (Gal & Ghahramani, 2016): одна и та же маска на всех шагах времени. Есть также **Zoneout** — с вероятностью p значение состояния просто копируется с прошлого шага.
- **BatchNorm в RNN работает плохо:** длина последовательностей разная, статистики на разных шагах времени различаются, running-статистики для длин, не встречавшихся при обучении, неверны. Стандарт — **Layer Normalization** (нормировка по признакам одного объекта на одном шаге, не зависит ни от батча, ни от длины).
- **Teacher forcing:** при обучении seq2seq-декодера на вход следующему шагу подают **истинный** предыдущий токен, а не сгенерированный. Обучение быстрее, но возникает расхождение между обучением и инференсом (exposure bias).
- Ещё: gradient clipping (почти обязательно), weight tying (общие матрицы входного эмбеддинга и выходного слоя), weight decay, early stopping.

<summary>Проверь себя</summary>

1. **Сколько параметров у LSTM с входом 100 и состоянием 256 (один bias)?** — *4·256·(256 + 100 + 1) = 365 568.*
2. **Почему clipping помогает от взрыва, но не от затухания?** — *Clipping только уменьшает слишком длинный градиент; маленький градиент он не увеличивает.*
3. **Что даёт forget gate ≈ 1 для градиента?** — *∂c_t/∂c_{t−1} ≈ I — градиент проходит без экспоненциального затухания.*
4. **Почему BiLSTM нельзя использовать для генерации текста?** — *Обратному проходу нужны будущие токены, которых при генерации ещё нет.*
5. **Чем truncated BPTT платит за экономию памяти?** — *Градиент не видит зависимостей длиннее k шагов (хотя прямой проход состояние передаёт).*
