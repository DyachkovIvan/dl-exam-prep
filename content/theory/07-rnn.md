# Тема 7. Рекуррентные сети: RNN, BPTT, BiRNN, LSTM, GRU, Dropout и BatchNorm в RNN

## 7.1 Основные понятия

- **Последовательность** — упорядоченный набор элементов x₁, …, x_T: слова текста, отсчёты звука, значения временного ряда.
- **Токен** — элемент текста, с которым работает модель (слово или часть слова).
- **One-hot вектор** — вектор длины словаря, где единица стоит на позиции слова. **Эмбеддинг** — плотный обучаемый вектор слова небольшой размерности.
- **Шаг времени t** — позиция в последовательности.
- **Скрытое состояние hₜ (вектор контекста)** — вектор фиксированной длины, который хранит информацию о уже прочитанной части последовательности. Его длина не зависит от длины текста.
- **Рекуррентная связь** — состояние прошлого шага подаётся на вход текущего.
- **Развёртка (unrolling)** — представление RNN как глубокой сети из T копий одного блока с общими весами.
- **Языковая модель** — модель, предсказывающая следующий токен по предыдущим.
- **Teacher forcing** — на обучении на вход следующему шагу подаётся правильный предыдущий токен, а не предсказанный.
- **Вентиль (gate)** — сигмоидный множитель от 0 до 1, решающий, какую долю информации пропустить.

## 7.2 Рекуррентная нейронная сеть (RNN)

**Определение.** RNN — класс нейронных сетей для последовательных данных, в котором состояние, вычисленное на прошлом шаге, подаётся на вход текущего шага. Так сеть учитывает контекст всех предыдущих элементов.

**Простыми словами.** Читаем текст слово за словом и держим в голове «краткое содержание прочитанного». Каждое новое слово обновляет это содержание.

**Рекуррентный блок:**
1. Взять текущий вектор контекста hₜ₋₁ и вектор токена xₜ.
2. Объединить их (сумма линейных преобразований, что эквивалентно конкатенации и умножению на матрицу).
3. Применить нелинейность — получить обновлённый контекст той же размерности.
4. По контексту предсказать выход (например, следующий токен).

$$h_t = \tanh(W_{hh}h_{t-1} + W_{xh}x_t + b_h), \qquad y_t = g(W_{hy}h_t + b_y), \qquad h_0 = 0$$

g — softmax для предсказания токена или sigmoid для бинарной классификации. В нотации CS230: a⟨t⟩ = g₁(W_aa·a⟨t−1⟩ + W_ax·x⟨t⟩ + b_a), y⟨t⟩ = g₂(W_ya·a⟨t⟩ + b_y).

**Ключевое свойство — общие веса.** Все блоки используют одни и те же матрицы W_hh, W_xh, W_hy. Поэтому сеть работает с последовательностями любой длины, а число параметров от длины не зависит: h(h + n + 1) для слоя с состоянием h и входом n.

**Как обучать языковую модель.** После каждого обновления контекста предсказываем следующий токен, сравниваем с реальным (кросс-энтропия), суммируем потери по шагам, считаем градиент (BPTT) и обновляем веса.

**Типы задач:** many-to-one (классификация текста), one-to-many (подпись к картинке), many-to-many синхронно (разметка слов, NER), many-to-many с задержкой (перевод, seq2seq).

**Почему в RNN используют tanh и sigmoid, а не ReLU.** Одна и та же матрица применяется на каждом шаге. С неограниченной активацией значения состояния могут расти от шага к шагу (сначала в [0, 10], потом в [20, 40] …), и сеть «взрывается». Ограниченные tanh и sigmoid держат состояние в фиксированном диапазоне. ReLU-RNN возможны, но требуют аккуратной инициализации (например, единичной матрицей — IRNN).

**Плюсы:** последовательности любой длины; мало параметров благодаря общим весам; естественная модель для потоковых данных.
**Минусы:**
- **затухание и взрыв градиента** → плохо помнит далёкий контекст;
- **нет параллелизма по времени** — шаг t ждёт шаг t − 1;
- каждый вход меняет контекст — модель может «забыть» полезное из-за шума.

## 7.3 Генерация текста и её проблемы

**Как генерируют:**
1. На вход подаётся технический токен ⟨START⟩.
2. Модель выдаёт распределение следующего токена; из него выбирают токен (argmax или сэмплирование).
3. Выбранный токен подаётся на вход следующему шагу.
4. Повторяют, пока не выдан ⟨END⟩ или не достигнута максимальная длина.

**Проблемы:**
- **накопление ошибок (exposure bias):** на обучении модель видела правильные префиксы (teacher forcing), а при генерации — свои. Одна ошибка в начале — и все следующие токены обусловлены на неё;
- модель может слишком рано выдать ⟨END⟩;
- жадный выбор даёт однообразный текст; используют beam search, сэмплирование с температурой, top-k, top-p.

## 7.4 Backpropagation Through Time (BPTT)

**Определение.** BPTT — обратное распространение ошибки для рекуррентных сетей: сеть разворачивается по времени в глубокую сеть из T копий блока с общими весами, и к ней применяется обычный backprop.

**Простыми словами.** Градиент относительно повторяющейся матрицы весов — это **сумма градиентов по каждому шагу времени**.

**Алгоритм:**
1. Прямой проход по всем T шагам, сохраняя все hₜ.
2. Суммарная потеря L = Σₜ Lₜ.
3. Обратный проход от последнего шага к первому: градиент идёт и к выходу шага, и к прошлому состоянию.
4. Градиенты общих весов со всех шагов **суммируются**.
5. Обновление весов оптимизатором.

**Чем отличается от backprop в сети прямого распространения:**
- градиент распространяется не только по слоям, но и **назад во времени**;
- одни и те же веса получают вклад с каждого шага → градиенты суммируются;
- эффективная глубина = длина последовательности → сильные затухание и взрыв;
- нельзя распараллелить по времени, память растёт с длиной;
- на практике — **Truncated BPTT**: градиент протягивают только на k последних шагов.

**Почему градиент затухает или взрывается** (Pascanu, Mikolov, Bengio, 2013). λ₁ — наибольшее сингулярное значение W_hh, γ — верхняя граница |σ′| (1 для tanh, 1/4 для sigmoid):
- **λ₁ < 1/γ — достаточное условие затухания** градиента;
- **λ₁ > 1/γ — необходимое (но не достаточное) условие взрыва.**

**Лечение взрыва — gradient clipping:** если ‖g‖ ≥ τ, то g ← τ·g/‖g‖. От затухания clipping не помогает — нужны LSTM и GRU.

<details>
<summary>Подробнее: формула градиента BPTT</summary>

$$\frac{\partial L}{\partial W_{hh}} = \sum_{t=1}^{T}\sum_{k=1}^{t} \frac{\partial L_t}{\partial h_t}\Bigg(\prod_{j=k+1}^{t}\frac{\partial h_j}{\partial h_{j-1}}\Bigg)\frac{\partial^{+} h_k}{\partial W_{hh}},
\qquad
\frac{\partial h_j}{\partial h_{j-1}} = \operatorname{diag}\big(1-h_j^2\big)\,W_{hh}$$

∂⁺h_k/∂W — «непосредственная» производная на шаге k при фиксированном h_{k−1}. Вклад шага k в потерю на шаге t проходит через произведение t − k якобианов: ‖∂h_j/∂h_{j−1}‖ ≤ γλ₁, и при γλ₁ < 1 произведение убывает экспоненциально.

</details>

## 7.5 Двунаправленные RNN (BiRNN)

**Определение.** Две независимые RNN: одна читает последовательность от начала к концу, другая — от конца к началу. Состояния на каждом шаге конкатенируются: hₜ = [hₜ→ ; hₜ←].

**Простыми словами.** Когда вся последовательность известна заранее, смысл слова можно понять и по предыдущим, и по следующим словам.

**Где:** классификация тональности текста, NER, разметка частей речи, энкодер в переводе — задачи, где весь вход доступен сразу.

**Плюсы:** каждый шаг видит **и прошлый, и будущий** контекст — заметно лучше качество разметки.
**Минусы:**
- **не подходит для потоковых задач и генерации:** обратному проходу нужны будущие элементы, которых ещё нет;
- вдвое больше параметров и вычислений.

## 7.6 LSTM (Long Short-Term Memory)

**Определение.** LSTM (Hochreiter & Schmidhuber, 1997; forget gate — Gers et al., 2000) — рекуррентный блок с **двумя состояниями**: долговременной памятью (cell state) cₜ и краткосрочным состоянием hₜ. Потоком информации управляют три вентиля.

**Простыми словами.** Модель сама решает, что запомнить, что забыть и что показать наружу, вместо того чтобы переписывать весь контекст на каждом шаге.

**Работа блока по шагам:**
1. **Forget gate fₜ** — для каждого элемента долговременной памяти решает, сохранить его (≈1) или забыть (≈0).
2. **Забыть часть памяти:** поэлементно умножить cₜ₋₁ на fₜ.
3. **Input gate iₜ** — решает, какие элементы памяти обновлять.
4. **Кандидат c̃ₜ** — новая информация (tanh от входа и прошлого состояния).
5. **Записать в память:** прибавить к памяти кандидат, отфильтрованный iₜ.
6. **Output gate oₜ** — решает, какую часть памяти выдать в краткосрочное состояние hₜ.

$$f_t = \sigma(W_f[h_{t-1},x_t]+b_f), \quad i_t = \sigma(W_i[h_{t-1},x_t]+b_i), \quad o_t = \sigma(W_o[h_{t-1},x_t]+b_o)$$
$$\tilde c_t = \tanh(W_c[h_{t-1},x_t]+b_c), \qquad c_t = f_t \odot c_{t-1} + i_t \odot \tilde c_t, \qquad h_t = o_t \odot \tanh(c_t)$$

[hₜ₋₁, xₜ] — конкатенация векторов.

**Почему LSTM не страдает от затухания.** Над долговременной памятью выполняются только поэлементное умножение на вентиль и сложение — без умножения на матрицу весов и без производной активации:
$$\frac{\partial c_t}{\partial c_{t-1}} = \operatorname{diag}(f_t) \quad(+\text{ вклады через вентили})$$

Если forget gate ≈ 1, градиент проходит через сотни шагов почти без изменений («constant error carousel»). Практический трюк — инициализировать bias forget gate единицей (Jozefowicz et al., 2015).

**Параметры:** 4 набора весов → 4·h(h + n + 1).

**Плюсы:** помнит длинный контекст; устойчивый стандарт до трансформеров.
**Минусы:** в 4 раза больше параметров, чем у простой RNN; медленнее; всё ещё последовательная обработка.

## 7.7 GRU (Gated Recurrent Unit)

**Определение.** GRU (Cho et al., 2014) — упрощение LSTM: **два** вентиля и одно состояние hₜ (нет отдельной долговременной памяти).

**Вентили и обновление:**
$$z_t = \sigma(W_z[h_{t-1},x_t] + b_z), \qquad r_t = \sigma(W_r[h_{t-1},x_t] + b_r)$$
$$\tilde h_t = \tanh(W[r_t \odot h_{t-1},\ x_t] + b), \qquad h_t = (1-z_t)\odot h_{t-1} + z_t \odot \tilde h_t$$

- **Update gate zₜ** — объединяет forget и input: какую долю состояния заменить новым.
- **Reset gate rₜ** — сколько прошлого состояния учитывать при построении кандидата.

> ⚠️ В статье Cho et al. и в PyTorch hₜ = zₜ⊙hₜ₋₁ + (1 − zₜ)⊙h̃ₜ — роль z перевёрнута. Суть та же; на экзамене скажите, какую конвенцию используете.

**LSTM vs GRU:**

| | LSTM | GRU |
|---|---|---|
| Вентили | 3 (forget, input, output) | 2 (update, reset) |
| Состояния | cₜ и hₜ | только hₜ |
| Параметры | 4·h(h+n+1) | 3·h(h+n+1) — около 3/4 от LSTM |
| Скорость | медленнее | быстрее |
| Качество | чуть лучше помнит очень длинный контекст | часто сопоставимо |

**Практика:** LSTM — хороший базовый вариант; GRU — если важна скорость.

## 7.8 Dropout в RNN

**Проблема.** Наивный dropout с новой маской на каждом шаге применённый к рекуррентной связи «зашумляет» память на каждом шаге, и сеть не может хранить информацию долго.

**Подходы:**
1. **Dropout на эмбеддингах слов** — случайно зануляются целые векторы слов словаря; маска одна на батч и применяется перед прямым проходом. Как и обычный dropout, остальные значения масштабируются на 1/(1 − p).
2. **Dropout только на нерекуррентных связях** (Zaremba et al., 2014) — между слоями и на входе/выходе, скрытые состояния hₜ₋₁ → hₜ не трогаются.
3. **Variational dropout** (Gal & Ghahramani, 2016) — **одна и та же маска на всех шагах времени** для входов, выходов и рекуррентных связей. Шум не накапливается от шага к шагу.
4. **Recurrent dropout** (Semeniuta et al., 2016) — для LSTM и GRU выключается часть **вектора обновления** i ⊙ c̃ внутри блока, а не само состояние: память не стирается, ограничивается только запись нового.

**Zoneout** (Krueger et al., 2017) — с вероятностью p элемент состояния просто копируется с прошлого шага.

## 7.9 Batch Normalization в RNN

**Почему обычный BN плохо подходит:**
- длины последовательностей разные, а статистики на разных шагах времени различаются;
- для длин, не встречавшихся на обучении, нет running-статистик;
- нормализация рекуррентной связи может нарушить поток градиента.

**Recurrent Batch Normalization** (Cooijmans et al., 2016):
- **отдельно** нормируются рекуррентный член W_h·hₜ₋₁ и входной член W_x·xₜ;
- линия долговременной памяти cₜ = fₜ⊙cₜ₋₁ + iₜ⊙c̃ₜ не нормируется, чтобы сохранить поток градиента (нормируется только cₜ при вычислении выхода hₜ);
- **статистики свои для каждого шага времени** (на тесте — усреднённые по обучению; для шагов длиннее обучающих берут статистики последнего шага); параметры γ, β общие для всех шагов;
- γ лучше инициализировать маленьким (**0.1**), иначе tanh насыщается и градиенты затухают.

$$\begin{pmatrix} f_t\\ i_t\\ o_t\\ g_t\end{pmatrix} = \mathrm{BN}(W_h h_{t-1};\gamma_h) + \mathrm{BN}(W_x x_t;\gamma_x) + b, \qquad h_t = \sigma(o_t)\odot\tanh\big(\mathrm{BN}(c_t;\gamma_c,\beta_c)\big)$$

**Стандарт на практике — Layer Normalization** (Ba et al., 2016): нормирует признаки одного объекта на одном шаге, не зависит ни от батча, ни от длины последовательности.

## 7.10 Прочие приёмы

- **Gradient clipping** — почти обязателен для RNN.
- **Weight tying** — одна матрица для входных эмбеддингов и выходного слоя.
- **Teacher forcing** на обучении + scheduled sampling против exposure bias.
- Weight decay, early stopping.

<details>
<summary>Проверь себя</summary>

1. **Сколько параметров у LSTM с входом 100 и состоянием 256 (один bias)?** — *4·256·(256 + 100 + 1) = 365 568.*
2. **Почему clipping помогает от взрыва, но не от затухания?** — *Он только уменьшает слишком длинный градиент.*
3. **Что даёт forget gate ≈ 1 для градиента?** — *∂cₜ/∂cₜ₋₁ ≈ I — градиент проходит без затухания.*
4. **Почему BiLSTM нельзя использовать для генерации текста?** — *Обратному проходу нужны будущие токены.*
5. **Чем variational dropout отличается от наивного dropout в RNN?** — *Маска одна на все шаги времени, поэтому шум не разрушает память.*
6. **Зачем в Recurrent BN статистики для каждого шага отдельно?** — *Распределение активаций на разных шагах времени разное.*

</details>
