# Тема 3. Регуляризация: Dropout, Batch Normalization (и соседи)

## 3.1 Зачем регуляризация

Переобучение = модель запомнила обучающую выборку (низкая train-ошибка, высокая val-ошибка). Регуляризация ограничивает эффективную сложность модели.

Что борется с переобучением:
- **L1/L2 (weight decay)** — штраф за большие веса (L1 даёт разреженность, L2 — «сжатие»),
- **Dropout**,
- **Early stopping**,
- **Data augmentation**,
- **Batch/Layer Normalization** (частично, за счёт шума в батче),
- увеличение датасета, уменьшение модели, label smoothing.

> ⚠️ **Pooling — НЕ метод регуляризации.** Это способ уменьшить пространственное разрешение (downsampling) и получить инвариантность к сдвигу. Это ответ на вопрос «какая стратегия НЕ предотвращает переобучение: Early stopping / Dropout / Data augmentation / **Pooling**».

## 3.2 Dropout

**Что делает:** на каждом шаге обучения случайно «выключает» нейроны с вероятностью p (обнуляет их выходы), каждый раз новая маска.

**Зачем:** нейроны не могут полагаться на конкретных соседей (борьба с co-adaptation); эффект — обучение **ансамбля экспоненциально многих подсетей** с общими весами.

**Train vs inference (любимая ловушка):**
- На обучении: маска применяется, оставшиеся активации делятся на (1−p) — *inverted dropout*.
- На инференсе: dropout **выключен**, используется вся сеть без масштабирования.

Типичные p: 0.5 для полносвязных, 0.1–0.3 для свёрточных (в CNN чаще используют **Spatial Dropout** — выключают целые каналы). В RNN — **variational dropout**: одна и та же маска на все шаги времени, иначе шум разрушает память.

Минусы: замедляет сходимость; плохо сочетается с BatchNorm (конфликт дисперсий — на практике ставят BN, а dropout только в голове сети или вообще убирают).

## 3.3 Batch Normalization

**Формула** (по каждому признаку/каналу, статистики по батчу):
$$\mu_B = \frac1m\sum x_i, \quad \sigma_B^2 = \frac1m\sum (x_i-\mu_B)^2$$
$$\hat x_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \varepsilon}}, \qquad y_i = \gamma \hat x_i + \beta$$
γ и β — **обучаемые** параметры (scale и shift), они позволяют сети при необходимости отменить нормализацию.

**Зачем:**
- стабилизирует и **ускоряет обучение**, позволяет брать больший learning rate;
- уменьшает зависимость от инициализации;
- сглаживает ландшафт функции потерь (современное объяснение; исходное объяснение через «internal covariate shift» сейчас считают неточным);
- даёт **лёгкий регуляризующий эффект** — статистики батча шумные, это похоже на шум dropout.

**Train vs inference:** на обучении используются статистики текущего батча; на инференсе — **накопленные скользящие средние (running mean/var) по всему обучению**. Поэтому на инференсе результат не зависит от того, с кем объект попал в батч.

**Куда ставить:** обычно Linear/Conv → BN → активация (порядок BN-перед-активацией — канонический вариант из статьи).

**Минусы:** плохо работает при маленьком batch size (шумные статистики), неудобен для RNN и переменной длины → там используют **Layer Normalization** (нормировка по признакам одного объекта, не зависит от батча; стандарт в трансформерах). Есть ещё Instance Norm (стилизация), Group Norm (детекция/сегментация с маленькими батчами).

**Когда полезна нормализация данных вообще:** когда признаки в разных масштабах (метры vs рубли), когда используются методы, чувствительные к масштабу (градиентные, kNN, SVM), когда нужно ускорить сходимость и избежать доминирования одного признака.

## 3.4 Ловушки

- «BatchNorm похож на dropout?» — частично: **оба вносят шум и дают регуляризацию**, но механизм разный (нормализация статистик vs случайное отключение нейронов); BN главным образом ускоряет обучение, dropout главным образом регуляризует.
- «BN центрирует данные относительно всего датасета?» — **нет**, на обучении относительно **текущего мини-батча**; приближение к статистикам датасета получается только на инференсе через running statistics.
- BN добавляет 2 обучаемых параметра на канал (γ, β) + 2 буфера (running mean/var, необучаемые).
